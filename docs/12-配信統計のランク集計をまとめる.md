# 配信統計のランク集計をまとめる

対象: ISUCON13 練習（ISUPipe / Go 参考実装）  
変更ファイル: `go/stats_handler.go` の `getLivestreamStatisticsHandler`（ランク算出部分のみ）  
目的: `GET /api/livestream/:livestream_id/statistics` のランク計算で、全配信に対する N+1（1配信2クエリ）を1本の集計 SQL にまとめる。

関連: [チャット引き継ぎ](./10-チャット引き継ぎ.md) の 6.3、[ユーザー統計のランク集計をまとめる](./09-ユーザー統計のランク集計をまとめる.md)

---

## 背景

- 最適化前 CPU pprof で `getLivestreamStatisticsHandler` の cum が 1.64 秒（ユーザー統計より CPU サンプルが多い）。
- 旧実装は `SELECT * FROM livestreams` のあと、配信ごとにリアクション `COUNT(*)` と tip の `SUM` を1本ずつ実行していた。

## 対象 API

| HTTP | ハンドラ |
|------|----------|
| `GET /api/livestream/:livestream_id/statistics` | `getLivestreamStatisticsHandler` |

今回触るのは **ランク算出**のみ。同関数内の次は変更しない。

- 視聴者数（`livestream_viewers_history`）
- 最大チップ（`MAX(tip)`）
- 対象配信のリアクション総数
- スパム報告数

## 旧実装

1. `SELECT * FROM livestreams` で全配信を取得
2. 各配信に対して次を2本ずつ実行

```sql
SELECT COUNT(*) FROM livestreams l
INNER JOIN reactions r ON l.id = r.livestream_id
WHERE l.id = ?

SELECT IFNULL(SUM(l2.tip), 0) FROM livestreams l
INNER JOIN livecomments l2 ON l.id = l2.livestream_id
WHERE l.id = ?
```

3. `score := reactions + totalTips` で `LivestreamRanking` を組み立て、`sort.Sort`（score 昇順、同点は livestream ID 昇順）後、対象 ID の順位を末尾から数える（変更なし）。

リアクションもチップも無い配信は `GetContext` が行なしとなり 0 のまま。スコア 0 でランキングに含まれる。

---

## 新実装

`livestreams` を起点に、リアクション数・チップ合計をサブクエリで `GROUP BY livestream_id` し、`LEFT JOIN` で全配信を1行ずつ返す。

```sql
SELECT
  l.id AS livestream_id,
  IFNULL(rc.reaction_count, 0) AS reactions,
  IFNULL(tc.tip_sum, 0) AS tips
FROM livestreams l
LEFT JOIN (
  SELECT livestream_id, COUNT(*) AS reaction_count
  FROM reactions
  GROUP BY livestream_id
) rc ON rc.livestream_id = l.id
LEFT JOIN (
  SELECT livestream_id, IFNULL(SUM(tip), 0) AS tip_sum
  FROM livecomments
  GROUP BY livestream_id
) tc ON tc.livestream_id = l.id
```

Go 側は各行で `Score: reactions + tips` とし、以降の `sort.Sort` と順位計算は旧と同じ。
